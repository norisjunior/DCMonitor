DCMonitor · teste no WSL antes do servidor

0/0

Ambiente de teste na sua máquina (10.32.9.23), com os quatro PRs juntos (branch feat/https-node-red). O ambiente atual do servidor continua no ar durante todo o teste: ele usa a porta 1883 e o novo usa a 8883. Na sua máquina, a stack usa as portas normais dos serviços; o que ocupar essas portas é parado na fase 4.

As marcações ficam salvas neste navegador. Clique no título de uma fase para recolhê-la.

0

Pré-requisitos no WSL

  1. Docker responde dentro do WSL. Anote se é o Docker Desktop (integração WSL) ou um Docker instalado no próprio WSL: isso muda a fase 6.

    WSL
    docker version --format '{{.Server.Os}} / {{.Server.Version}}'
docker context ls

    Contexto desktop-linux = Docker Desktop.

  2. Git e OpenSSL instalados.

    WSL
    sudo apt update && sudo apt install -y git openssl
1

Código

  1. Clonar em /FdctIoTPlatform/DCMonitor, no sistema de arquivos do WSL, não em /mnt/c: lá o chown para os UIDs dos containers não funciona.

    WSL
    sudo install -d -o "$USER" /FdctIoTPlatform
git clone https://github.com/norisjunior/DCMonitor.git /FdctIoTPlatform/DCMonitor
cd /FdctIoTPlatform/DCMonitor
git checkout feat/https-node-red
git log --oneline -1
2

Certificados e diretórios

  1. Gerar a CA de teste e os certificados do broker e do Node-RED com o IP da sua máquina.

    WSL · /FdctIoTPlatform/DCMonitor
    sudo MQTT_TLS_IPS="10.32.9.23" bash scripts/gerar_certificados.sh

  2. Conferir os nomes no certificado.

    WSL · /FdctIoTPlatform/DCMonitor
    openssl x509 -in pki/mosquitto/server.crt -noout -ext subjectAltName
ls -ln pki/mosquitto/server.key pki/node-red/server.key

    Esperado: DNS:localhost, DNS:10.32.9.23, IP Address:10.32.9.23; chaves com dono 1883 e 1000.

  3. Criar os diretórios de credenciais MQTT e do cadastro.

    WSL · /FdctIoTPlatform/DCMonitor
    sudo install -d -o 1883 -g 1883 ./mqtt-seguranca
sudo install -d -o 1000 -g 1000 ./cadastro
3

Arquivo .env

  1. Criar o .env a partir do exemplo.

    WSL · /FdctIoTPlatform/DCMonitor
    cp .env.example .env && chmod 600 .env

  2. Gerar os segredos aleatórios e colar no .env: MQTT_ADMIN_PASSWORD, INFLUXDB_ADMIN_PASSWORD, INFLUXDB_TOKEN, NODE_RED_CREDENTIAL_SECRET, N8N_ENCRYPTION_KEY e GRAFANA_ADMIN_PASSWORD. Rode uma vez para cada um.

    WSL
    openssl rand -base64 32

    A MQTT_ADMIN_PASSWORD precisa de ao menos 24 caracteres; sem isso o Mosquitto não sobe.

  3. Gerar os dois hashes de login: um para o editor do Node-RED (NODE_RED_ADMIN_PASSWORD_HASH) e outro para a página de cadastro (CADASTRO_ADMIN_PASSWORD_HASH). O comando pede a senha; anote as duas senhas originais.

    WSL
    docker run --rm -it --entrypoint node-red nodered/node-red:4.1.11 admin hash-pw

    No .env, cada hash vai entre aspas simples, por causa dos caracteres $. O login do editor é o usuário admin; o da página de cadastro é o usuário cadastro.

  4. Decidir o Zabbix do teste. Mantendo ZABBIX_SERVER=10.32.8.57 e ZABBIX_SERVER_2=10.32.8.69, a placa em teste continua alimentando os hosts reais. Para não enviar nada, deixe os dois vazios e ignore os erros de envio no log.

  5. Conferir que não sobrou nenhum TROQUE_.

    WSL · /FdctIoTPlatform/DCMonitor
    grep -n 'TROQUE_' .env || echo "ok, nenhum TROQUE_"
4

Portas livres

  1. A stack usa as portas normais: 1880 (Node-RED), 3000 (Grafana), 5678 (n8n), 8086 (InfluxDB) e 8883 (MQTT com TLS). Ver se algum container já ocupa alguma delas.

    WSL
    docker ps --format '{{.Names}}\t{{.Ports}}' | grep -E ':(1880|3000|5678|8086|8883)->' || echo "portas livres"

    Esperado: portas livres, ou a lista dos containers que ocupam as portas.

  2. Parar os containers listados no passo anterior e anotar os nomes no campo do fim da página, para religá-los depois do teste. Troque os nomes pelos da lista.

    WSL
    docker stop NOME1 NOME2

    Se nenhum container aparece, mas a stack não sobe por porta ocupada, procure um programa do Windows na porta: Get-NetTCPConnection -State Listen -LocalPort 1880,3000,5678,8086,8883 no PowerShell.

  3. Conferir que o Compose lê o .env sem erro.

    WSL · /FdctIoTPlatform/DCMonitor
    docker compose config -q && echo "compose ok"
5

Subir a stack

  1. Construir e subir.

    WSL · /FdctIoTPlatform/DCMonitor
    docker compose up -d --build

  2. Esperar um minuto e conferir que tudo está saudável.

    WSL · /FdctIoTPlatform/DCMonitor
    docker compose ps --format '{{.Service}}  {{.Status}}'

    Esperado: healthy em mosquitto, influxdb, node-red, grafana e n8n.

  3. Conferir a primeira subida do broker e a conexão do Node-RED.

    WSL · /FdctIoTPlatform/DCMonitor
    docker compose logs mosquitto | grep iniciar
docker compose logs node-red | grep -E 'Connected to broker|cadastro vazio'

    Esperado: credenciais base criadas, Connected to broker e criando cadastro vazio.

    Se o node-red não sobe: docker compose logs node-red | tail -30. Mensagens sobre certificado ou CADASTRO_ADMIN_PASSWORD_HASH apontam o que falta.

6

Windows: confiar na CA e abrir a porta 8883

  1. Copiar o certificado público da CA de teste para a pasta Downloads do Windows. A primeira linha descobre a pasta do seu usuário.

    WSL · /FdctIoTPlatform/DCMonitor
    DESTINO="$(wslpath "$(powershell.exe -NoProfile -Command '$env:USERPROFILE' | tr -d '\r')")/Downloads"
sudo cp pki/ca/ca.crt "$DESTINO/dcmonitor-ca-teste.crt" && ls -l "$DESTINO/dcmonitor-ca-teste.crt"

  2. Instalar como autoridade raiz confiável.

    PowerShell como administrador
    certutil -addstore -f Root $env:USERPROFILE\Downloads\dcmonitor-ca-teste.crt

    Depois do teste, remova esta CA: certutil -delstore Root "DCMonitor CA". A do servidor será outra.

  3. Liberar a 8883 no firewall do Windows para a placa alcançar o broker.

    PowerShell como administrador
    New-NetFirewallRule -DisplayName "DCMonitor MQTT TLS (teste)" -Direction Inbound -Protocol TCP -LocalPort 8883 -Action Allow

    Docker instalado dentro do WSL (não Desktop): ative networkingMode=mirrored em %USERPROFILE%\.wslconfig e rode wsl --shutdown, senão a placa não chega à 8883.

  4. Testar a porta pelo IP da rede.

    PowerShell
    Test-NetConnection 10.32.9.23 -Port 8883

    Esperado: TcpTestSucceeded : True.

  5. Abrir a página de cadastro. O navegador não pode mostrar aviso de site não seguro.

    Navegador
    https://localhost:1880/admin/

    Usuário cadastro (o valor de CADASTRO_ADMIN_USER), não admin. O admin é só do editor, em https://localhost:1880/. Usuário errado responde Unauthorized. Se o navegador não pedir de novo o login, feche todas as janelas dele ou use uma janela anônima.

    Para conferir se uma senha bate com o hash do .env sem deixá-la no histórico: read -rs -p "Senha: " S; echo; printf %s "$S" | docker compose exec -T node-red node -e 'let d="";process.stdin.on("data",c=>d+=c).on("end",()=>console.log(require("bcryptjs").compareSync(d,process.env.CADASTRO_ADMIN_PASSWORD_HASH)))'; unset S (deve mostrar true).

7

Ensaio sem a placa

  1. Na página, em Placa nova, digite esp32-0000000000A1 e clique em Gerar senha. Copie a senha da linha mostrada (o último campo).

  2. Publicar uma leitura com essa senha, pelo TLS, de dentro do container do broker. Troque SENHA pela senha copiada.

    WSL · /FdctIoTPlatform/DCMonitor
    docker compose exec mosquitto mosquitto_pub -h localhost -p 8883 --cafile /mosquitto/certs/ca.crt \
  -u esp32-0000000000A1 -P 'SENHA' -t fdctmon/esp32-0000000000A1/data \
  -m '{"device_id":"esp32-0000000000A1","sensor":"DHT22","temp":23.4,"umid":51.2}'

    Sem saída = aceito. Na página, a linha da placa passa a mostrar a leitura.

  3. Revogar a credencial de ensaio na página (Revogar, dois cliques) e repetir o comando anterior.

    Esperado: not authorised.

8

Placa real

  1. Levar o certificado da CA para o projeto que você compila no Windows. Ajuste o destino para a pasta do seu projeto.

    WSL · /FdctIoTPlatform/DCMonitor
    cp ESP32/include/ca_cert.hpp /mnt/c/GitHub/DCMonitor/ESP32/include/

  2. No projeto do Windows, usar a mesma branch do teste.

    PowerShell · C:\GitHub\DCMonitor
    git fetch; git checkout feat/https-node-red

  3. Ajustar o ESP32/include/config.hpp local (pode apagar MQTT_USERNAME e MQTT_PASSWORD, que não são mais usados):

    config.hpp
    constexpr char MQTT_HOST[] = "10.32.9.23";
constexpr uint16_t MQTT_PORT = 8883;
constexpr char NTP_SERVIDOR[] = "pool.ntp.org";
constexpr char VERSAO_FIRMWARE[] = "1.6.0";

    O Windows não serve NTP; use o pool.ntp.org ou o NTP da instituição. O TLS não depende de hora, só o display.

  4. Apagar a flash e gravar. Depois, abrir o monitor serial.

    PowerShell · ESP32
    pio run -t erase
pio run -t upload
pio device monitor

    Esperado no serial: [CREDENCIAL] Este dispositivo ainda não tem senha MQTT com o ID da placa; o OLED mostra Sem credencial. Enter repete as instruções.

  5. Na página, gerar a senha com o ID mostrado no serial. Clicar em Copiar linha, colar no monitor serial e teclar Enter.

    Esperado: Senha gravada. Reiniciando...

  6. Acompanhar o primeiro ciclo no serial.

    Esperado: Conectando ao MQTT 10.32.9.23:8883 (TLS), Publicado em fdctmon/<ID>/data e, em seguida, o deep sleep de 60 s.

    Se aparecer credencial recusada: confira se a linha colada é a última gerada. MQTT indisponível: refaça o teste de porta da fase 6.

  7. Na página, criar o local (por exemplo, Biblioteca), dar nome à placa, escolher o local e Salvar alterações.

  8. No Grafana, conferir a placa com o nome amigável e o painel Situação das placas.

    Navegador
    http://localhost:3000

  9. Deixar rodando alguns ciclos: as leituras chegam a cada ~60 s e a coluna Sem dados há fica verde.

9

Antes de ir para o servidor

  1. Anotar no campo abaixo o que precisou de ajuste neste teste, para corrigir no repositório antes da troca.

  2. Entendido: no servidor, a PKI é gerada do zero, sem MQTT_TLS_IPS. A CA de teste não vai para produção. As placas testadas aqui serão regravadas com o ca_cert.hpp do servidor, com MQTT_HOST do servidor, e recebem senha nova na página do servidor. Credenciais e cadastro do teste não migram.

  3. Limpar o teste na sua máquina quando terminar: derrubar a stack, religar os containers parados na fase 4 (nomes anotados abaixo), remover a regra de firewall e a CA de teste do Windows.

    WSL · /FdctIoTPlatform/DCMonitor
    docker compose down
docker start NOME1 NOME2
    PowerShell como administrador
    Remove-NetFirewallRule -DisplayName "DCMonitor MQTT TLS (teste)"
certutil -delstore Root "DCMonitor CA"
